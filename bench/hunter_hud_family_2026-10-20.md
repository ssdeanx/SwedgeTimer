## 2. What changed

### 2.1 One owner for the per-family id (`classes/hunter.lua:130`)

`SPELL_ID_BY_FAMILY` — one table, one entry per (slot key, family), every cell
cited in the comment above it. The **HUD slot** and the **guide slot** of a key
read the same entry, so the two surfaces can never disagree about which spell the
running client has. A family with **no** entry for a key cannot have that spell:
the HUD's dead-slot filter drops the slot and the guide's slot set does not
declare it.

The Steady Shot keeps its own owner (`steady_id_by_family`, the steady lane's
table) and is the `steady` entry of the new table, so there is still exactly one
owner per key.

### 2.2 The client's own rank re-points every HUD slot (`classes/hunter.lua:2212`)

One loop replaces the two single-slot loops the steady lane shipped: the rank
that re-points a guide slot re-points the HUD slot of the same key. The Aimed
Shot walks **its family's** ladder (`hud_aimed_rank_ids`: the vanilla ladder on
the classic-line clients, the TBC r7 27065 and the WotLK instant shot 49050
elsewhere) — the vanilla table alone would leave the TBC and the WotLK slot on a
rank the client does not have as its Aimed Shot.

### 2.3 The family filter grows one cell (`classes/hunter.lua:2986`)

`FOREVER = { steady = true, kill_command = true }` — the Forever client has no
Kill Command (§1.1/§1.2), so the HUD ships **seven** slots there, not eight. The
Forever guide set already declared no Kill Command slot, so the two surfaces now
agree.

### 2.4 The gather spends two fewer reads per tick on the classic-line clients

A slot for a spell the client cannot have carries **no id**, so the gather reads
no cooldown for it: the Era/SoD gather spends 4 reads (was 6) and the Forever
gather 3 (was 4). No prompt is lost — those spells are not in those families'
rotations either.

### 2.5 The frozen spec was re-cut (`hunter_guide.lua:16`)

The guide's display-slot block carried the old family-blind ids (2973 / 2643 /
19434) and the over-generalised claim that 56641 "exists on no client past 2.2"
(the WotLK, Cata, Mists and retail clients all carry it). Both are corrected to
the shipped per-family ids.

## 3. The pick channel (the operator's filing, 2026-10-20)

**The comment lied; the behaviour was already right.** `classes/hunter.lua` said
*"The engine's drill press carries no action, so the live cast is the player's own
pick"* — true before the F1 fix (bench/drill_pick_contract_2026-10-20.md §3),
false after it: the drill-list **PRESS** now wins, and the class's live-cast pick
survives only a **press-LESS** drill press.

* The class's ctx publisher (`practice_context`) and the class drills' header
  comment now say the shipped contract: the press is written into every alias the
  graders read (`ctx.pick` among them, and this class's reader reads `ctx.pick`
  FIRST), so **a press grades the press**; the live cast survives only a
  press-less press (and on the scenario path, a different call site).
* The reader's own comment was sharpened the same way.
* The stale reason in the test file's clip-drill comment was corrected ("the
  engine's drill press carries no action" → "it reads no press at all").

**The two cases are now pinned in the hunter's own suite**
(`tests/hunter_guide_state.lua`, the drill section):

| case | pin |
|---|---|
| a press grades the press | `order(..., { now = 100, pick = "silencing_shot" })` → "S"; `{ pick = "steady" }` → "F"; `{ pick = "steady", pressed = "silencing_shot" }` → "F" and `{ pick = "silencing_shot", action = "steady" }` → "S" (ctx.pick wins over every other alias) |
| a press-less drill press judges the live cast | the class's own ctx publishes the live cast: `practice_context(...)` with a live Steady Shot → `ctx.pick == "steady"`, and the drill grades **that** ("F" at the Wrath fixture, where the live cast is not the rotation's answer); with no live cast → `ctx.pick == nil` and the drill grades nothing |

The end-to-end half (the drill-list press overwriting the class's published pick)

## 2. Gate expression and lifecycle

### 2.1 The exact gate (no side effects before the last layer)

```lua
local function client_can_have_aura_rows()
    if st.family ~= "FOREVER" then return false, "family" end
    if global_table("C_AuraContainerUtil") == nil then return false, "C_AuraContainerUtil" end
    if global_table("AuraContainerSortMethod") == nil then return false, "AuraContainerSortMethod" end
    if global_table("AuraContainerSortDirection") == nil then return false, "AuraContainerSortDirection" end
    return true, "ok"
end
A.available, A.gate_reason = client_can_have_aura_rows()   -- evaluated at file load
```

- Layer 1 is `st.family == "FOREVER"` — the repo's authoritative discriminator (`compat.lua`). It is
  deliberately **not** `st.is_mainline`: Forever is Mainline-code, but Retail is too.
- Layers 2-4 are `rawget(_G, ...)` type checks. `Blizzard_AuraContainer` is not LoadOnDemand
  (`## AllowLoad: game`, `Blizzard_AuraContainer.toc`) and re-exports both sort tables
  (`_G.AuraContainerSortMethod = securecopy(...)`, `Blizzard_AuraContainerShared.lua:262-263`), so
  all three globals exist when user addons load. Verified against `origin/forever` tip `eac30af5`.
- Layer 3 (the CreateFrame probe) is the `pcall(CreateFrame, "AuraContainer", name, UIParent,
  "CustomAuraContainerTemplate, DisableUntrustedLayoutScriptsTemplate")` inside `create_container`
  (735-748); on failure it retries without the second template, then reports a retryable failure.
- A failed gate is a **silent no-op**: no frame, no event, no aura read, no option side effect, and
  no printed notice (the option controls are hidden by the same answer).

### 2.2 Lifecycle

```
file load (every client)
  └─ st.family ~= "FOREVER" ──► A.available = false; every function returns immediately
  └─ FOREVER + globals        ──► A.available = true

main.lua post_init (after bars exist, after power_bar.init)
  └─ ST:init_aura_icons() [pcall(A.init, self)]
       ├─ not available / inert            → false (non-Forever: one pcall + one compare)
       ├─ ready                            → true (idempotent)
       ├─ class has no list (fail closed)  → false, no frame at all
       ├─ no CreateFrame/UIParent          → A.inert = true (permanent, environment limit)
       ├─ driver = plain Frame             → created (also during lockdown: it is the retry engine)
       ├─ InCombatLockdown()               → A.state.deferred = "combat"; NO AuraContainer; false
       ├─ attempts += 1
       ├─ build_row("buffs")  → AuraContainer + SetSize(1,1)/strata/SetUnit + AddAuraGroup("buffs","HELPFUL",{...})
       ├─ build_row("debuffs")→ AuraContainer + AddAuraGroup("debuffs","HARMFUL|PLAYER",{...})
       ├─ created any → A.state.layout = nil (one explicit layout push for all rows)
       ├─ A.state.ready = true; sync_layout(); anchor(force)
       └─ true

driver OnUpdate (0.15 s maintenance; 0 forces a pass)
  └─ not ready → retry_create (0.5 s interval, no latch; reuses a half-built container)
  └─ ready     → sync_layout (size/spacing/grow) → anchor (topmost visible bar, fixed band)

driver OnEvent PLAYER_ENTERING_WORLD → forced anchor pass (or one init retry)
options setter → A.apply_settings(ST) → sync_layout + forced anchor (immediate)
```

### 2.3 The fixed reserved band (the secret-geometry rule)

```
+------------------------ buff row (HELPFUL, player) ------------------------+
+------------------------ debuff row (HARMFUL|PLAYER) ----------------------+   bottom = bar_top + 6
======================= topmost visible swing bar ============================
buff bottom = bar_top + 6 + (debuff row visible ? icon_size + 16 : 0)
```

The client writes container geometry through `secretwrap`
(`Blizzard_CustomAuraContainer.lua:794-801`), so a container's height/top can be secret. The module
never reads `GetHeight/GetWidth/GetTop/GetBottom/GetLeft/GetPoint/GetSize/IsShown` on a container
(the fake client frame in the suite counts every such call and the suite asserts zero). The 16 px is
the reference's `DEBUFF_TEXT_CLEARANCE` (room for the client's duration text above debuff icons); the
6 px gap also clears the 5 px duration bar (3 px bar + 2 px gap) that hangs below a debuff icon.

Top bar selection uses only the addon's own swing-bar frames: `ST:iter_hands()` +
`ST:get_bar_frame(hand)`, shown check + `GetTop()`, highest wins, exact tie keeps the first hand in
class order. A secret/unreadable `GetTop` or `IsShown` is skipped, never compared. Any
`SetPoint`/`Show`/`Hide` failure is pcall-isolated and retried on the next 0.15 s pass (taint rules
in combat are UNCONFIRMED; see §6 U8).

### 2.4 Cross-client inertness (proved by the suite)

On ERA/TBC/WRATH/CATA/MISTS/RETAIL the suite asserts: `available == false`, `gate()` reason
`"family"`, `init` false, **zero** frames created, **zero** events registered, **zero
`AuraContainer` creation attempts**, **zero** aura reads, the secrecy predicate never consulted,
`apply_settings`/`on_update` stay inert, diagnostics still answers. On top of that the only runtime
delta on a classic client at login is `post_init`'s `pcall(A.init, self)` returning at its first
comparison, and 6 additional hidden widgets in the Behaviour options page (hidden ⇒ not rendered).

## 7. Decisions, deviations and risks

1. **Driver frame is created during combat; native containers are not.** The brief's hard rule is
   "creation never happens in combat lockdown" — the native `AuraContainer` creation is what could be
   tainted/protected, so it is deferred. A plain non-secure `Frame` (the retry driver) is safe to
   create and is the only way the module can retry without a class-file hook (class files are out of
   scope). The suite asserts ZERO `AuraContainer` frames in lockdown; the module never touches the
   swing bars (`ST:show_bar`/`hide_bar` call counters stay 0).
2. **`option_table_presets.lua` untouched** — no HUD template needs aura keys; the brief allowed
   skipping it and it keeps the template diff out of this lane.
3. **`aura_icons.lua` is in the single TOC and loads on every client** by design (the runtime gate is
   the isolation mechanism). On classic clients its load cost is the family compare + table/function
   definitions; no frame/event/read.
4. **Fixed band instead of measuring the debuff row** (report §6.5; the client's `secretwrap` sizing
   makes a measurement unsafe). Cosmetic consequence documented in the module header: the buff row
   sits one band higher than strictly needed when the debuff row is hidden.
5. **`maxDuration = 180` on the buff row** hides permanent/passive auras, so talent-record ids
   (Flurry 12319, Maelstrom 408498, druid passives 16958/1223246/417051) never paint a permanent icon.
6. **Shared/racial merge is buff-row only and copied at creation time.** The client securecopies
   `includeSpellIDs` (`Blizzard_CustomAuraContainer.lua:236-240`), so later table mutation would be
   invisible anyway; the class arrays stay pure.
7. **Size changes resize the existing buttons** (`GetAuraGroupFrameCount`/`GetAuraGroupFrame` +
   `SetSize`), because the group layout only positions buttons — the size lives on the button. The
   frame count is treated as possibly secret (skipped, never compared).
8. **`C_Secrets` is consulted only by `diagnostics().aura_secret`** (fail-closed). It never gates the
   row: the native path is correct in both secrecy states, and the suite proves identical container
   calls with auras secret or readable.
9. **No classic fallback** (confirmed by t2: `UnitAura` does not exist on Forever; reader APIs are
   `RequiresNonSecretAura`). The module contains no aura-data code path at all.
10. **Concurrent-tree note:** this workspace is shared with the other lanes in the team; files
    outside this task's write scope (`hud.lua`, `compat.lua`, `LibGlobalCooldown.lua`, some tests)
    were being modified by other lanes during this session. The evidence above is from runs of THIS
    tree at the stated moments; `bash tests/run.sh` was green end-to-end at the final run.

## 8. Operator-facing summary

The Forever client now gets two native aura icon rows anchored above the topmost visible swing bar:
your temporary buffs (plus shared/racial procs) and the target debuffs you applied yourself. It is
built from the client's own `AuraContainer` system, so it declares spell ids and never reads aura
data — which is why it keeps working under the Forever secret-value regime. On every other client the
module is completely inert. The row is per-class (six classes; a class with no list creates nothing),
defaults ON for Forever, and can be toggled / sized / spaced / grown from `/st` → Behaviour → "Aura
icons (WoW Forever)". The debuff row is empty on friendly targets by the client's own identity-filter
rule, and includes your pet's/vehicle's applications (the `PLAYER` filter token).
